## 1. Must fix before go-live

**Server: authorization.** Items 1–6 are fixed on `fix/ci-and-audit`, with regression tests in
`server/tests/unit/authorization.hardening.test.js` and `rateLimit.test.js`. Summary:
- Shows: the create/update field whitelist is in place, and `organization_id` can't be changed.
- Reads: show/org/user reads require auth and are scoped to the caller.
- Membership: show access requires an active org membership, and leaving an org removes its show memberships.
- Show roles: hierarchy is enforced for edits made to *other* members, including removing them.
- Org roles: only a president can grant or revoke `president` or act on a president.
- Login/sign-up: an in-memory rate limiter is added (set `TRUST_PROXY` behind a proxy).
- Still open: a "last president" guard. Adding it would break existing test setups that swap the creator's president role for admin, so it needs a follow-up.
1. **Critical: show mass-assignment allows cross-tenant writes.** `show.service.js:172` passes `req.body` straight to `show.update()`. A director can set `organization_id` to another org. After that, the inventory, invite and calendar code trusts the new org, so the director can read and edit that org's master inventory and invite into it. Whitelist `title/start_date/end_date`, never allow `organization_id` to change, and whitelist `create()` (`:138`, which also accepts `id`).
2. **High: user directory dump.** `GET /api/users` returns every user's email and phone to any logged-in account, and sign-up is public. Remove the endpoint or scope it to shared orgs, and return only name fields.
3. **High: org removal doesn't revoke show access.** `authorizeShow` and `authorizeInventoryDept` fall back to the ShowMembership without checking that the user is still in the org. Require an active OrgMembership, and remove the ShowMemberships when someone leaves the org.
4. **High: role escalation.** The hierarchy check in `showRole.service.js:32` only runs when users edit *their own* roles. A stage-manager can strip the director, or promote an alt account to director. Org roles have no hierarchy at all and no "last president" guard.
5. **High: no rate limiting** on login or sign-up, and the password policy is only "8 characters". Add `express-rate-limit` and set `trust proxy` correctly.
6. Already known: `GET /api/shows`, `/api/shows/:id`, `/api/orgs` and `/api/orgs/:id` are unauthenticated, and `/api/shows/user` without `orgId` returns every show.

**Deployment**
7. **Critical: the built client can't reach the API.** `client/src/services/config.js` falls back to `http://localhost:8050`. CI builds without `VITE_BACKEND_URL`, and compose bakes in `https://localhost:8050` against an HTTP-only server. Fix: call same-origin `/api` and proxy `/api` and `/uploads` in nginx.
8. **Critical: compose has no MySQL service or data volume.** No healthchecks, `API_PORT` is undocumented (default 5000 vs. 8050 everywhere else), and `NODE_ENV=production` is never set, so 500 errors leak internal messages.
9. **Critical: schema and reference data.** Startup `sync()` failures are only logged and the server keeps serving. There are no migrations. Roles and departments only come from `seed.js` (demo data, wipes the DB) or the reset endpoint, so a fresh prod DB has none.
10. **High:** no TLS anywhere. The CI client image is hand-written (`nginx:alpine`, root, `EXPOSE 80` while nginx listens on 8080). nginx keeps its default 1 MB body limit while uploads allow 5 MB. Images are only tagged `:latest`, so there's no rollback.

## 2. Should fix soon after

- Changing email or password doesn't require the current password, and tokens can't be revoked. Add `tokenVersion`.
- If `ALLOW_DB_RESET` is ever set in prod, any user can wipe the DB. `seed.js` has no environment guard.
- `DB_SSL` is parsed but never passed to Sequelize, and the string `"false"` counts as truthy.
- Uploads are never deleted when replaced or removed. Make sure a volume or object storage is used.
- Budget totals concatenate strings (DECIMAL comes back as a string): `show.service.js:230`.
- Deleting an org or show orphans its children. No `onDelete` is set. Possibly an authz bypass through `org_id IS NULL` (unverified).
- Show-level department crew can edit org-wide global inventory items.
- Org oversight roles (board-member) bypass `requiredRoles`, so they can delete shows. Confirm this is intended.
- Seeded department names (Scenic, Lighting, Sound) never match role names (sets, tech), so those departments are unusable.
- Multi-step writes are not wrapped in transactions (role replacement, invite response, item creation).
- Client: pages swallow load errors and render blank, there's no React ErrorBoundary, and `PrivateRoute` only checks that a token string exists.

## 3. Polish and hardening

- Add helmet/HSTS. `CORS_ORIGIN` defaults to `*`. Login timing and messages allow user enumeration. Multer errors return 500. Uploads trust the client's MIME type.
- Show members (including actors) see everyone's email and phone, plus the budget.
- JWT is stored in localStorage. CSP mitigates this, but httpOnly cookies are better long term.
- Unfinished UI: "Manage Budget" only `console.log`s, there are "under construction" tabs, the literal text "Bio placeholder", and native `alert`/`prompt` dialogs.
- nginx: no gzip, no cache headers for `/assets` vs `index.html`.
- Graceful shutdown, a DB-aware health check, and structured logging.
- Timezones: no Sequelize `timezone` is set and there's no `end > start` validation.
- Docker base images use `node:20` (EOL). Move to `node:24`. Replace `npm ci --only=production` with `--omit=dev`.
- README Docker/env sections are wrong: they omit `JWT_SECRET`, `CORS_ORIGIN` and `API_PORT`, and list the wrong ports.
